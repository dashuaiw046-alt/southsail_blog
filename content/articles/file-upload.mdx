# 文件上传漏洞学习笔记

安全上传需要同时校验扩展名、实际文件类型、大小与存储位置，并避免让上传目录可执行。

## 为什么容易出错

上传功能同时涉及：

1. 文件名
2. 内容类型
3. 存储路径
4. 后续访问方式

任何一环把用户可控数据直接交给文件系统或 Web 服务器，都可能变成执行入口。

## 检查清单

- 生成服务端文件名，不要信任原始文件名。
- 使用白名单扩展名，而不是黑名单。
- 校验文件头，而不是只看 `Content-Type`。
- 限制大小，避免资源耗尽。
- 将文件存储在 Web 根目录之外。
- 上传目录关闭脚本执行。

## 一个最小处理流程

```python title="upload.py"
from pathlib import Path
import uuid

ALLOWED = {".png", ".jpg", ".jpeg", ".gif"}

def store_upload(original_name: str, data: bytes, dest: Path) -> Path:
    suffix = Path(original_name).suffix.lower()
    if suffix not in ALLOWED:
        raise ValueError("unsupported type")
    target = dest / f"{uuid.uuid4().hex}{suffix}"
    target.write_bytes(data)
    return target
```

## 常见绕过思路

- 双扩展名：`shell.php.png`
- 大小写：`.PhP`
- 空字节或特殊分隔符
- 伪造 MIME
- 图片马：合法图片里夹带脚本

> 不要假设“前端已经过滤过”。所有检查都必须在服务端完成。
