# SSRF + XXE

# 1. 什么叫 SSRF？

SSRF：

> **Server-Side Request Forgery，服务端请求伪造。**

最简单理解：

```text
正常：

你 → Web服务器 → 外部网站
```

SSRF：

```text
你
 ↓
Web服务器
 ↓
内网 / 本机 / 其他服务器
```

也就是说：

> **你不是自己去访问目标，而是骗服务器替你访问。**

PortSwigger 对 SSRF 的定义也是：攻击者诱导服务器端应用向非预期位置发起请求。

***按照我对 SSRF 的理解，它就像“借刀杀人”：借服务器的能力访问服务器自己能访问、而我自己无权直接访问的资源。***

例如：

```text
我
 ↓
目标 Web 服务器
 ↓
127.0.0.1:8080
```

我的电脑可能无法访问目标服务器的：

```text
127.0.0.1:8080
```

但是目标服务器自己可以访问。

所以如果存在类似：

```php
$url = $_GET['url'];
echo file_get_contents($url);
```

就可能形成：

```text
/fetch.php?url=http://127.0.0.1:8080/admin
```

服务器实际上是在：

```text
目标服务器 → 127.0.0.1:8080
```

------

## SSRF 的核心不是“访问 127.0.0.1”

`127.0.0.1` 只是一个非常典型的目标。

真正应该理解的是：

> **服务器替我发起请求。**

因此可能关注：

```text
本机服务
内网 IP
内部 API
内部管理页面
其他端口
云环境内部资源
```

------

## SSRF 的基本请求链

```text
攻击者
   ↓
Web服务器
   ↓
服务器发起请求
   ↓
目标资源
   ↓
响应
   ↓
根据应用逻辑决定是否返回给攻击者
```

------

## 反射型 SSRF

如果服务器访问目标之后：

```text
服务器 → 内部服务
           ↓
         响应
           ↓
服务器 → 攻击者
```

攻击者可以直接看到响应内容。

例如：

```text
Welcome Admin
Flag{xxxx}
```

这种可以理解为：

> **有回显的 SSRF。**

------

## Blind SSRF

如果服务器确实发出了请求，但是：

```text
内部服务
   ↓
响应
   ↓
没有直接返回给攻击者
```

就是：

> **Blind SSRF（盲 SSRF）。**

这时候需要通过其他现象判断请求是否发生，例如：

```text
响应差异
状态码
错误信息
延迟
其他可观察的外部行为
```

------

## SSRF 过滤

例如：

```php
if (strpos($url, '127.0.0.1') !== false) {
    die('blocked');
}
```

这种过滤的问题是：

> **它只检查用户输入的字符串，而不是服务器最终访问的目标。**

所以分析 SSRF 时应该思考：

```text
用户输入 URL
     ↓
URL 解析
     ↓
Host
     ↓
地址解析
     ↓
最终 IP
     ↓
服务器真正访问的目标
```

因此：

> **输入看起来安全 ≠ 最终访问目标安全。**

还需要考虑：

```text
域名解析
IP 表示方式
重定向
协议
端口
内网地址
```

------

## SSRF 和 CSRF 的区别

### SSRF

> **借服务器的网络能力。**

```text
攻击者 → 服务器 → 目标
```

### CSRF

> **借用户浏览器的登录身份/权限。**

```text
攻击者 → 用户浏览器 → 目标网站
```

可以简单记：

```text
SSRF：借服务器

CSRF：借用户
```

------

# 2. 什么叫 XXE？

XXE：

> **XML External Entity，XML 外部实体注入。**

理解 XXE 之前，先理解 XML。

------

# 3. 先了解 XML

XML 的全称是：

> **Extensible Markup Language，可扩展标记语言。**

先抓住两个词：

- **标记语言**：用标签把数据包起来，告诉解析器“这块是什么”。
- **可扩展**：标签名不是固定死的，可以根据数据自己定义。

例如：

```xml
<student>
    <name>张三</name>
    <age>18</age>
</student>
```

可以理解成：

```text
student
├── name = 张三
└── age = 18
```

***我的理解：XML 就像一种“可以自定义标签的类 HTML 文本”，主要用于描述和组织数据。***

HTML 更偏向：

> **描述网页怎么显示。**

XML 更偏向：

> **描述数据是什么、数据怎么组织。**

------

# 4. XML Parser

XML 后面能变成：

```text
Entity
 ↓
External Entity
 ↓
XXE
```

前提是：

> **服务器拿到了一段 XML，然后交给 XML Parser（XML 解析器）解析。**

XML Parser 不是简单地：

```text
“把 XML 显示出来”
```

而是：

```text
XML 文本
 ↓
XML Parser
 ↓
解析标签、属性、实体等结构
 ↓
生成程序可以使用的数据
```

所以 XXE 的关键对象其实是：

> **XML Parser。**

------

# 5. Entity 是什么？

XML 可以定义 Entity（实体）。

例如：

```xml
<!DOCTYPE user [
    <!ENTITY name "southsail">
]>
```

可以暂时理解成：

```text
name → southsail
```

然后：

```xml
<username>&name;</username>
```

这里：

```text
&name;
```

就是：

> **实体引用。**

解析后可能变成：

```xml
<username>southsail</username>
```

所以：

```text
<!ENTITY name "southsail">
        ↓
     定义实体

&name;
   ↓
引用实体

southsail
```

------

# 6. External Entity

普通 Entity：

```xml
<!ENTITY name "southsail">
```

本质：

```text
name → 一个字符串
```

而 External Entity：

```xml
<!ENTITY name SYSTEM "外部资源">
```

这里的：

```text
SYSTEM
```

**不是 PHP 的 `system()`，不是执行操作系统命令。**

它是在 XML 中声明：

> **这个实体的内容来自一个外部资源。**

所以：

```text
普通 Entity

实体 → 字符串
```

而：

```text
External Entity

实体 → 外部资源
```

------

# 7. XXE 到底做了什么？

核心理解：

> **XML 的某些配置允许 XML Parser 处理 External Entity，于是解析 XML 时，解析器可能去读取外部资源。**

攻击链可以理解为：

```text
攻击者控制 XML
       ↓
XML Parser
       ↓
解析 External Entity
       ↓
访问外部资源
       ↓
产生安全影响
```

可能涉及：

```text
本地文件读取
内部网络访问
SSRF
敏感信息泄露
解析器资源消耗
```

------

# 8. XXE 的两个重要方向

## ① External Entity → 本地资源

如果外部实体指向本地资源：

```text
XML
 ↓
External Entity
 ↓
XML Parser
 ↓
读取本地资源
```

可能导致：

> **本地文件读取。**

当然，是否成功还取决于：

```text
解析器配置
操作系统权限
目标文件权限
应用逻辑
```

------

## ② External Entity → 远程资源

如果外部实体指向远程 URL：

```text
XML
 ↓
External Entity
 ↓
XML Parser
 ↓
服务器发起请求
 ↓
远程资源
```

那么它的行为就和 SSRF 的思想产生了联系：

> **服务器替你访问目标。**

因此：

```text
XXE
 ↓
External Entity
 ↓
服务器发起请求
 ↓
可能形成 SSRF
```

------

# 9. XXE 和 SSRF 的关系

这是这一阶段最重要的知识点之一。

### SSRF

```text
用户直接控制 URL
        ↓
服务器发请求
```

### XXE

```text
用户控制 XML
        ↓
External Entity
        ↓
XML Parser
        ↓
服务器访问外部资源
```

所以：

> **XXE 可以成为触发 SSRF 的一种途径。**

可以记成：

```text
                 ┌→ 本地资源读取
                 │
XXE → External Entity
                 │
                 └→ 外部请求 → SSRF
```

------

# 10. 目前我的理解

## SSRF

***借服务器之手。***

```text
我访问不到
     ↓
服务器可能访问得到
     ↓
让服务器替我访问
```

## XXE

***利用 XML Parser 对 External Entity 的处理。***

```text
我控制 XML
     ↓
定义 External Entity
     ↓
XML Parser 处理它
     ↓
可能读取资源 / 发起请求
```
